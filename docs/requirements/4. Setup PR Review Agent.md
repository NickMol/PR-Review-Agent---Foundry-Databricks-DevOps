# Setup PR Review Agent

The agent automatically reviews PRs in Azure DevOps by reading the changed files and posting findings as comments. It is triggered by an ADO pipeline, authenticates via a service connection, and runs inside Azure AI Foundry.

Full architecture: `docs/architecture/pr_review_agent.md`

---

## Prerequisites

| What | Role required | Where |
|---|---|---|
| Create/manage Foundry agents | Azure AI Developer | Foundry resource → IAM |
| Pipeline calls the agent | **Foundry User** | Foundry resource → IAM (assign to service connection SP) |
| Agent posts PR comments | Contribute to pull requests | ADO project → Repos → Permissions |

---

## Step 1 — Create the agent in Azure AI Foundry

1. Go to [ai.azure.com](https://ai.azure.com) → your project → **Agents** → **+ New agent**
2. Name: `pr-review-agent`
3. Model: select your GPT-4o deployment
4. **Instructions** — paste a system prompt telling the agent to:
   - Retrieve the PR diff and changed files using its ADO MCP tools
   - Search the platform rules document for relevant rules
   - Post a summary comment and inline findings on the PR
5. **Tools → File search** — upload `platform-rules.docx` (your platform standards document)
6. **Tools → MCP** — connect to the Azure DevOps repository (for reading PR diffs and file contents)
7. Save the agent

---

## Step 2 — Create the service connection in ADO

1. ADO project → **Project settings** → **Service connections** → **New service connection**
2. Type: **Azure Resource Manager** → **Workload identity federation (automatic)**
3. Select the subscription and resource group containing the Foundry resource
4. Name: `azure-devops-serviceconnection`
5. Save

---

## Step 3 — Grant the service connection Foundry User role

1. Azure Portal → your Foundry resource → **Access control (IAM)**
2. **Add role assignment** → **Foundry User**
3. Assign to the service principal created by the service connection
   - Find it by searching the service connection name or its object ID
4. Save

> Without this role the pipeline gets a 403 when trying to call the agent.

---

## Step 4 — Configure the variable group in ADO

1. ADO → **Pipelines** → **Library** → variable group `ai-foundry-config`
2. Ensure these variables are present:

| Variable | Value |
|---|---|
| `AI_FOUNDRY_ENDPOINT` | `https://<hub>.services.ai.azure.com/api/projects/<project>` |
| `AGENT_NAME` | `pr-review-agent` |

---

## Step 5 — Enable the pipeline

The pipeline file `medallion-poc/azure-pipelines-pr-review.yml` is already in the repo.

1. ADO → **Pipelines** → **New pipeline**
2. Select: **Azure Repos Git** → `medallion-poc` → **Existing Azure Pipelines YAML file**
3. Path: `/medallion-poc/azure-pipelines-pr-review.yml`
4. Save (do not run yet)
5. Authorize the pipeline to use the `ai-foundry-config` variable group when prompted

---

## How the pipeline works

When a PR is opened or updated targeting `dev`, `uat`, or `master`:

1. The pipeline installs the `azure-ai-projects` SDK
2. It authenticates to Foundry using the service connection (`DefaultAzureCredential` picks up the CLI session set up by `AzureCLI@2`)
3. It calls `get_openai_client(agent_name)` → `conversations.create()` → `responses.create()` with a prompt containing the PR number, repo, and project
4. The agent uses its MCP tools to read the PR diff, searches the rules document, and posts comments on the PR
5. The pipeline prints the agent's response and flags whether comments were confirmed

---

## Updating the platform rules

Upload a new version of `platform-rules.docx` to the Foundry file store and re-attach it to the agent's file search tool. No code changes needed.
