## How this repository was created

This repository was set up as a Databricks PoC (Proof of Concept) for a medallion architecture using Databricks best practices. The architecture and all code were designed and scaffolded through an interactive session with Claude Code (Anthropic).

### What was decided

The key design choices made during that session:

- **Lakeflow Declarative Pipelines (LDP)** instead of standard Databricks Jobs — LDP handles Auto Loader, CDC upserts, and Materialized Views natively, which matched the requirements directly.
- **One catalog per environment** (`dev`, `uat`, `prd`) rather than one catalog with environment-prefixed schemas, to give proper isolation between environments.
- **One pipeline covering all three layers** (Bronze → Silver → Gold), with fully-qualified table names so each layer lands in its own schema.
- **Databricks Asset Bundle (DAB)** for deployment, so schemas, volumes, and pipelines are all declared as code and created automatically on deploy.
- **Azure DevOps CI/CD** with three permanent branches (`dev`, `uat`, `master`) mapping directly to the three DAB targets, with PR-based promotion and approval gates on UAT and PRD.

### What was built

```
medallion-poc/
├── databricks.yml                          # Bundle: variables and dev/uat/prd targets
├── azure-pipelines.yml                     # Azure DevOps pipeline: validate on PR, deploy on merge
├── resources/
│   ├── schemas.yml                         # Creates bronze/silver/gold schemas on deploy
│   ├── volumes.yml                         # Creates orders_landing volume in bronze
│   └── medallion_pipeline.pipeline.yml     # LDP pipeline configuration
├── src/pipelines/medallion/transformations/
│   ├── bronze_orders.sql                   # Auto Loader → Streaming Table (all strings)
│   ├── silver_orders.sql                   # Auto CDC upsert → Streaming Table (typed, CamelCase)
│   └── gold_fact_orders_by_region.sql      # Materialized View aggregation
└── data/
    └── sample_orders.csv                   # Dummy order data for testing

docs/architecture/
├── architecture.md                         # Full data architecture design
└── cicd_azure_devops.md                    # CI/CD pipeline design and branching strategy
```
